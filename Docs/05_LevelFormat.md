# 05. ステージデータ仕様

ファイル：`Assets/PieceOfCake/Data/Levels/levels.json`（UTF-8）

## 1. 形式

```json
{
  "version": 1,
  "stages": [
    {
      "id": "stage1",
      "name": "ショートケーキの おか",
      "theme": "shortcake",
      "par": 0,
      "customer": "bear",
      "signs": ["◀ ▶ で いどう、ジャンプ で とぶ", "..."],
      "map": [
        "..........",
        "@.t...O.G.",
        "##########"
      ]
    }
  ]
}
```

| キー | 型 | 必須 | 説明 |
|---|---|---|---|
| `version` | int | ○ | 形式のバージョン。現在 `1` のみ対応 |
| `stages` | 配列 | ○ | 1〜100 件。並び順がステージ番号 |
| `id` | string | ○ | 一意な ID。セーブデータのキーになるので **公開後は変えない** |
| `name` | string | ○ | 表示名 |
| `theme` | string | — | テーマキー（[02_Definitions.md](02_Definitions.md#8-コンテンツのキー)） |
| `par` | int ≥ 0 | ○ | ★3 のロス上限 |
| `customer` | string | — | お客さんキー |
| `signs` | string[] | ○ | 看板 `t` の説明文。看板を **列（左→右）→ 行（上→下）** の順に並べたときの順番。数は `t` の数と一致させる |
| `map` | string[] | ○ | 上の行から順に。全行同じ長さ。幅 1〜512、高さ 1〜128 |

マップ記号は [02_Definitions.md](02_Definitions.md#2-マップ記号levelsjson-の-map) を参照。

## 2. 検証ルール

読み込み時（`LevelJson.Parse` → `LevelParser.Parse`）に次を検証し、1 つでも違反すると `LevelFormatException` になります。ゲームはエラー画面を表示し、コンソールに **ステージ ID と問題** を出します。

- ファイルが空、100 万文字超、JSON として不正、`version` が 1 以外
- ステージ 0 件、101 件以上、`id` の重複、空のステージ要素
- `id` / `name` が空、`par` が負
- マップが空、行の長さが不揃い、サイズ上限超え
- 未知の記号、`@` が 0 個または 2 個以上、`G` が 0 個または 2 個以上、`O` が 0 個、`o`（小文字）
- `t` の数と `signs` の数の不一致

## 3. ステージを追加・変更する手順

1. `levels.json` を編集する（Unity 外のエディタでも可）。
2. Unity で **Tools ▸ Piece of Cake ▸ Validate Levels** を実行し、エラーがないことを確認。
3. Play モードで遊んで確認。
4. ★3 の解法を `Tests/EditMode/Support/StageSolutions.cs` に追加し、テストを実行（[06_Testing.md](06_Testing.md)）。
   - 既存ステージを変更した場合、`PrototypeDeliveryFrames`（試作品との一致テスト）は値を更新するか、そのステージの一致テストを外します。
5. コミットしてプッシュ。

## 4. 設計のコツ

- 1 マス = シミュレーション 40px。通常ジャンプは約 2.25 マス、いちごパワーで約 3.6 マス、ゼリーで約 4.8 マス上がります。
- 幅 1・高さ n のケーキは倒すと **n マスの橋**（倒れる先の n−1 マスが空いている必要あり）。
- 押せる重さは 4 セル（チョコパワー中 12）。上に乗ったケーキも重さに含まれます。
- アイスは乗って 0.6 秒で溶けます。溶けたセルはロスになりませんが、支えを失って **落ちた** ケーキはロスになります。
