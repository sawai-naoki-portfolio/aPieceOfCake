# 09. 品質（非機能要件）

依頼にあった「脆弱性・堅牢性・運用性・保守性」に対して実施した対策です。

## 1. 脆弱性（セキュリティ）

| リスク | 対策 |
|---|---|
| 不正・巨大なステージデータによるメモリ枯渇 | ファイル 100 万文字、ステージ 100 件、マップ 512×128 の上限を読み込み前に検査（`LevelJson`, `LevelParser`） |
| 不正な記号・構造によるクラッシュ | 全項目を検証し、問題は `LevelFormatException` で 1 か所に集約。ゲームはエラー画面で安全に停止 |
| セーブデータの改ざん・破損 | ★は 0〜3 に丸め、ID の長さ・件数を制限、壊れた JSON は破棄（`PlayerPrefsProgressStore`） |
| 際限なく増えるイベント | イベントバッファの上限 512 件 |
| 外部通信・個人情報 | なし（ネットワーク、広告、解析 SDK を使っていない） |
| 外部コードの実行 | なし（`eval` 相当、動的ロード、リフレクションによる任意呼び出しを本番コードで使っていない） |

## 2. 堅牢性

| 項目 | 対策 |
|---|---|
| 設定漏れ | 起動時に `GameBootstrap` が全参照と `GameArt` の不足を検査し、**何が足りないか** をコンソールと画面に表示 |
| UI 定義とコードのずれ | `UiElements.Required` が要素名と型を検査し、欠けていれば名前付きで例外 |
| フレーム落ち | 1 フレーム最大 6 ステップ・最大 0.1 秒に制限（処理落ちの悪循環を防ぐ） |
| 入力の取りこぼし | 押下をステップまで保持（`PlayerControls`）。メニュー中は破棄して誤操作を防ぐ |
| 状態の不整合 | ルールの状態は `internal set` で外から書き換え不可。表示は状態を読むだけ |
| 決定性 | 乱数なし・固定ステップ・安定ソート。テストで同じ入力 → 同じ結果を確認 |
| 未知のテーマ・お客さん | 先頭の定義で代用して続行 |
| フォントがない環境 | 警告を出して既定フォントで続行 |

## 3. 運用性

| 項目 | 対策 |
|---|---|
| 再現できるセットアップ | モデル・マテリアル・カタログ・シーンをメニュー / スクリプトから再生成 |
| データ検証 | Tools ▸ Validate Levels で Play しなくても検証できる |
| 分かりやすいエラー | ログはすべて `[PieceOfCake]` 接頭辞付き。ステージ ID と問題を明記 |
| 手順書 | [07_Operations.md](07_Operations.md)（ビルド、セーブデータ、トラブル対応、Git） |
| バージョン管理 | `.gitignore` / `.gitattributes`（改行、YAML マージ、バイナリ指定）、小さなコミットで `main` に反映 |

## 4. 保守性

| 項目 | 対策 |
|---|---|
| 責務の分離 | Core（ルール）/ Game（表示・入出力）/ Editor / Tests の 4 アセンブリ。Core は UnityEngine 参照禁止 |
| 小さなクラス | 1 クラス 1 責務（[03_Architecture.md](03_Architecture.md#6-開発原則の適用)） |
| データ駆動 | ステージ = JSON、見た目 = `GameArt`、文言 = `Texts`、色 = マテリアル |
| 自動テスト | 53 件。全ステージの ★3 クリアと試作品との一致を毎回検証 |
| 不要コードの削除 | URP テンプレート（TutorialInfo, Readme, SampleScene, 既定の入力アクション）を削除。未使用の引数・定数を整理 |
| ドキュメント | 仕様・定義・設計・UML・データ形式・テスト・運用・アート・品質を `Docs/` に集約 |
